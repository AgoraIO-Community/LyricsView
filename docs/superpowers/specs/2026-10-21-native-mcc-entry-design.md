# Android 音集协入口切换为原生 MCC

## 已确认的需求

- Android Demo 的“音集协”入口映射到 `ServiceType.MCC`，通过当前本地 RTC SDK 的 `IAgoraMusicContentCenter` 与 `IAgoraMusicPlayer` 获取和播放歌曲。
- 选歌读取 `LyricsResourcePool.asMusicList()`，使用现有《爱情转移》《说爱你》《love story》《趁着你》4 首歌及其原生 MCC songCode。
- 使用 XML 歌词及其音高资料，RTC 提供麦克风音高，KaraokeView 使用内置计分。
- 首次启动、原 MCC_EX 和无效偏好均归一化为 MCC/XML；原 MCC 偏好保持 MCC/XML；已选择 TME 的用户保持 TME/LRC。
- 保留 MCCEx 插件依赖、实现和兼容类型；音集协页面不再初始化或调用 MCCEx 服务。
- 保留当前演唱页、选歌与设置入口、80% 屏高选歌面板和 TME 功能。
- 在已连接的华为 FIN_AL60a 真机上验证实际播放、歌词、麦克风计分、暂停/继续、拖动及原伴唱切换。

## 方案取舍

采用现有 ServiceManager 的 MCC 分支和 MccManager 实现，修改业务入口、偏好及选歌分发。这直接复用现有原生播放流程，改动范围符合用户确认的要求。

另一种方式是重写 MCCExManager 使其包装原生 MCC；这会混淆已有类名和服务语义，也会影响需要保留的插件兼容实现，因此不采用。

## 入口与状态

DemoServicePreferences 将所有非 TME 选择归一化为 MCC/XML。SettingsActivity 的“音集协”控件保存 MCC/XML，并正确展示当前服务和歌词类型。ServiceManager 的初始服务改为 MCC，确保首次初始化不经过插件。

选歌面板读取原生 MCC 的列表；宿主回调和 ServiceManager 选择方法使用 MCC 语义，根据真实列表位置更新当前歌曲。保留 MCCEx 原有可调用实现，避免为了本任务删除兼容路径。

MainActivity 的音集协默认歌词配置、组件内置计分状态及切换服务后的状态应与 MCC/XML 一致，避免继承上一首 MCCEx 的外部计分标记。默认启动不自动选歌播放。

## 播放与计分

选歌 → ServiceManager 的 MCC 选择分支 → 停止旧歌 → MCC 预加载 → getLyric(XML) → 歌词下载与解析 → 设置 KaraokeView 内置计分 → 原生音乐播放器 open(songCode, 0) → 打开完成后 play。

沿用原生 MCC 的原伴唱切换、暂停/继续和 seek。RTC 本地音高通过 ServiceManager 的 MCC 分支传入 KaraokeView；播放器位置驱动歌词同步。插件的 YSD 凭证与 token 服务不是此入口的初始化条件。

保留现有原生 MCC 的鉴权和歌曲编号，不复制 MCCEx 的供应商编号或歌曲参数。当前本地 RTC JAR 的实际接口是实现依据；不照搬集成文档中本地 JAR 不支持的 addVendor 示例。

## 失败处理与范围

验证中检查初始化、预加载、歌词下载、解析和播放器打开的实际结果。不能把模拟成功回调或界面跳转作为真实播放/计分成功的证据。

如果存在授权、网络、歌曲资料缺失或设备输入问题，记录具体歌曲和错误，区分客户端缺陷与服务侧限制；只修复本次原生 MCC 接入所必需的客户端问题。不会用 MCCEx 回退来掩盖原生路径失败。

- 验证打开/关闭选歌面板、旋转和 TME 已有行为。
