# 音集协与 TME 共用演唱页

用户已逐项确认本设计并同意实施。

## 页面与行为

两种服务直接共用 MainActivity、activity_main.xml 及同一个 KaraokeView，沿用音集协的布局、样式、歌词/评分开关、进度、回调区和所有按钮。保留服务对应的标题、选歌列表与设置入口。TME 的预加载、歌词/音高准备及错误信息进入原有描述和回调区。

TME 开放歌词拖动与跳过前奏；使用组件现有跳转计分规则。下一首按 TME 列表循环且自动播放；停止取消当前会话，再播放从当前歌曲开头重新准备。暂停/继续及原伴唱切换通过原有 TME 播放会话完成。设置中的歌词、评分、拖动及外观选项对两种服务生效。

音频可播放但计分资料失败时允许无计分播放。若 LRC 可用而音高缺失、无效或下载失败，保留歌词和进度同步；错误信息仍保留。播放器本身失败不伪装成无计分播放。

## 实现边界

推荐直接接入现有 MainActivity；抽取全新公共 Fragment 的方案改动更大，不采用。新增 TmeSingingPresenter 只连接共享控件与现有 TmePlaybackController，不创建独立页面。音集协继续走原有路径。兼容 TmeSingingActivity 复用 MainActivity，旧的 TME Fragment/XML 不再参与导航。

控制器补充受会话和状态保护的 seek；ServiceManager 记住所选 TME 歌曲，保证下一首、停止重播一致。计分准备组件增加默认关闭的仅歌词降级模式，Demo 显式启用；既有组件调用方维持严格计分准备契约。降级仍使用现有请求、下载、线程及清理机制，避免另外复制网络流程。

共享组件以兼容的 `KaraokeEvent.onSeekRequested` 默认方法允许媒体层拒绝拖动；旧 listener 默认仍调用 onDragTo 并接受，TME 返回播放器实际接受结果。拒绝时不清除得分。首次进入和 reset 后先安装空模型再 attachUi，保证无歌、准备中和停止后开关安全。

切服务、停止、销毁时取消旧会话；旧回调不可更新新歌曲。进入设置或后台暂停，返回后显式继续。旋转按现有 configChanges 保持页面；进程或 Activity 重建后不恢复已经丢失的计分采样，显示中断，允许播放按钮从头重启当前歌曲。

## 验证

控制器测试覆盖 seek 的状态保护、成功/失败及暂停保持；准备测试覆盖缺音高、音高下载失败/超时、解析失败时保留 LRC、取消和迟到回调。页面回归改为验证共享控件、准备后再播放、开关及设置、选歌面板、服务切换、停止重播与重建。构建应用和设备测试 APK，运行主机 TME 准备、控制器及 JNI 计分测试。有设备时执行真机回归；无设备则明确记录未执行项目。
